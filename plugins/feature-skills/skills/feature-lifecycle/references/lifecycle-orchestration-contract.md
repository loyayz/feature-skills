# Lifecycle 编排契约

本文件只定义编排、资产、接口检查和异常路由。三个能力独占需求、实现、评审及验证判断。

## 状态与基线

各 Stage 按序自动推进。消费能力结果或发生阶段转换时，原位更新流程文档的当前阶段、结果和仍未解决项，替换已失效的“运行中”“未进入”“待决定”等表述；固化提交和资源解绑后，同样原位更新当前 HEAD、待执行动作和资源状态，不靠末尾追加新状态覆盖旧状态。原始失败留在日志或报告中，当前正文引用最终结论及其限制。只在真实业务决定、授权缺口、执行阻塞或用户停止边界暂停。用户要求执行到 Stage 4 之前时，整合准备完成后停止；普通状态消息或先前的一般继续不能解除边界。

`initial-base-sha` 永久保留流程起点；`delivery-base-sha` 是当前 feature 已完成对齐的交付基线，初始等于前者。评审 diff、整合 manifest、soft reset 和单提交证明使用后者。只有 rebase 完成且目标 SHA 已是 feature 祖先时才推进；仅 base 引用前进、rebase 开始或 abort 都不更新。冲突恢复由 Stage 4 路由，不能把 base 的提交重新计入 feature 交付。

## 能力接口与路由

调用能力使用运行时原生显式加载机制。只传普通目标、事实、路径、授权与已有证据；不接管内部依赖、调查方法、方案、执行预算、评审算法、代理或验证策略。用户给出的资料和 finding 原样作为事实输入；能力语义取证由能力自己负责。

接口检查只确认返回状态、必要结果和限制是否完整，实际产物存在且内容身份匹配，是否有未解决阻塞或返回间的明确矛盾。内容身份与所声明的实际修改范围可机械核对，业务正确性由能力判定。结果缺失或矛盾时把具体缺口退回对应能力；同一缺口重复返回时保留证据并暂停，不代写结论、不重复专业工作，也不把技术接口失败转成业务问题。

| 能力结果 | 编排动作 |
|---|---|
| spec 的 `implementation-ready` | 接口检查后提交最终 spec，保存结果并进入 Stage 2 |
| dev 的 `completed` | 保存实现与验证证据，进入 Stage 3 |
| review 的 `completed` 且没有阻塞项 | 保存报告及最终内容身份，进入整合准备 |
| `requires-user-decision` | 保持当前工作，只询问最小决定 |
| `requires-user-authorization` | 披露具体权限缺口，保留资产等待授权 |
| `requirements-change-needed` | 回 Stage 1，把变化交给 spec 收敛，再经过开发和评审 |
| `blocked`、失败或能力预算耗尽 | 保留能力证据并暂停，不额外循环延长预算 |

Spec 完成判断及收敛证据由 spec 自查并返回；lifecycle 可保存其摘要或引用，不解析内部步骤顺序、revision 或重建收敛状态机。review 的完成判断由 review 自查并返回；整合只消费其状态、目标内容、阻塞项与限制，不重复要求内部评审步骤的证明。

## 命令与交付证据

执行本 skill 自有命令前读取适用项目指令，确认工作目录、路径、工具、shell、参数和退出语义。未知路径先用文件列表或定向搜索定位，不按目录命名猜测；按实际宿主准备命令，不猜测工具链或把未解析变量当作环境变量。复杂 PowerShell 先检查语法，替换或补丁后核对实际落盘结果，不能以命令已执行代替修正已生效。成功输出只保留必要值，失败保留原命令、退出码和最小错误片段；大量输出在源头压缩或保存为派生产物。

实现和验证命令由相应能力选择与执行，lifecycle 不在能力之间追加构建、测试或专业检查。用户要求跳过的范围随输入传递，并保留能力返回的静态验证或未验证结论。

保存和传递 dev/review 已返回的实际验证证据：内容身份、完整命令、工作目录、配置与环境、覆盖范围、退出码与结论，以及日志或报告引用（若有）。review 负责复用、补充或失效判断，并给出原因；lifecycle 不重分类、不规定表格状态转换、不因登记缺项重跑验证。未知字段如实记录；未知不能证明可复用，需要的结论缺乏依据时退回能力处理。

整合前将 review 返回的最终内容身份记为 `final-review-snapshot`。此后仅核对交付内容与该身份的关系；Stage 4 的历史对齐例外由其整合规则定义，不将旧证据改写成新运行结果。

## 自有机械执行

按共享低成本协议选择执行方式；Stage 4 的最新状态会立即决定 Git 写操作，由主代理直接执行，这是正常职责，不登记为例外。

本 skill 的低成本代理身份为 `编排阶段 + 工作目录 + 单一任务域`；整合准备使用 `integration-preparation`，不是 Stage 3。阶段、目录或任务域变化时新建代理，旧句柄不再接收任务；身份不变时按共享协议判断续用。能力内部代理和等待由能力管理，不镜像到本 skill。

有独立工作时先继续；真正等待时用运行时原生事件机制，时长按宿主允许范围配置，避免重复短轮询。实际执行选择不依赖观测记录是否完整。

## 临时目标观测（稳定后删除）

本节及流程文档的同名区只用于验证项目目标，不属于交付门禁。后续确认所有目标稳定后，删除临时台账、统计与专用检查；删除不得影响能力调用、验证复用、授权、Git 或清理。

优先引用运行时现成事件，仅在有观察价值时紧凑记录 lifecycle 自己的派生、续用、等待和直接执行原因。没有自有事件不创建占位行；未公开字段写 `unavailable`，不从名称推断。能力的开发代理、reviewer、内部等待和验证调度即使由同一主代理执行，也不汇总到此区；评估它们直接引用原始任务及已有输出。能力返回的交付结论和验证依据保存在交付证据区，不混入临时观测。

可随工作更新，缺项不阻塞、不要求先填表再执行、不触发对账门禁或额外查询、验证、用户确认。缺少观测只能使目标评估为证据不足。交付所需身份、验证依据或授权缺口仍按接口与安全规则处理，不能用观测非阻塞绕过。

## 外层集成观察

只有用户同时明确启动本 skill，并显式启用将其声明为 required sub-skill 的外层集成时才启用；单独调用没有观察者。外层集成的依赖声明不能替代用户对本 skill 的启动授权。该集成的产品用途独立于临时目标观测。

可观察已成立的 `lifecycle_initialized`、阶段或阻塞变化、spec 已提交且路径确定、实现或评审进度、整合后清理前的完成状态。外层可维护自己的命名元数据小节，不接管状态、授权、过程资产或业务语义。

每个实际观察点只执行一次外层动作，不下放代理，不启动或修复外部服务；失败不重试、不阻塞或改变交付与清理。

## 过程资产与异常

流程文档、评审报告、用户要求的可选实施计划、诊断和构建中间产物属于过程资产；最终 spec 和用户明确要求的交付文档不自动归入过程资产。过程文件不得进入 feature 提交，只记录需披露的流程文档、报告、manifest 和特殊资源入口，不建立 ignored 输出清理白名单。

Stage 4 合并授权覆盖成功后的整个隔离 worktree 清理；删除前仍检查注册身份、绝对路径和外部链接。最终文档只保留当前有效结果，流程状态不得成为第二份业务规范。

初始化或安全检查失败时保留实际路径与错误，不退回原工作区实施、不自动删除用户资产。能力不可用或执行失败时暂停；验证失败交还产生证据的能力，lifecycle 不重跑相同命令。Git 写操作失败按 Stage 4 规则处理。
