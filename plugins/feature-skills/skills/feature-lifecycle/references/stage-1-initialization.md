# Stage 1 内部初始化

只在 `SKILL.md` 进入 Stage 1 初始化预检后完整读取本文件。原工作区不干净时不创建流程；预检通过后在 Stage 1 内创建 worktree 和生命周期文档。

初始化只取得用户资料和仓库身份，不承担需求调查或方案判断。worktree 创建并验证后，所有交付文档、代码、评审、测试和提交都在 worktree 中完成；用户明确要求的可选实施计划也留在该 worktree。

## 需求来源

- 已有需求文档：直接记录路径，不重复询问。
- 没有需求文档：Stage 1 spec 兼作需求文档，生成后回填实际路径。
- 用户提供的项目资料作为能力输入；资料是否不足以判断需求由能力决定。
- slug 由用户指定值或原始请求中的英文关键词自动生成，不展示、不确认。分支名固定为 `feat/YYYY-MM-DD-<feature-slug>`。

## worktree 初始化

以下连续初始化批次包含创建分支和 worktree 的 Git 写操作，固定由主代理直接执行，不下放低成本代理，也不为它提前读取该协议。主代理使用当前宿主和运行时的原生能力完成批次，不固定 shell 命令文本。连续初始化批次不等于单个大脚本：先以短小的当前 shell 原生命令完成只读预检，在当前任务状态中汇总所需事实，再单独进入 Git 写操作；只有共享进程状态或原子一致性确实需要时才使用复合脚本。批次在首次真实执行前须满足编排契约的“命令就绪”条件；语法、shell 或参数尚未就绪时不得用真实初始化命令试错。该批次只做下列身份、冲突、路径和 worktree 操作；输出只保留后续步骤实际使用的仓库根、base、SHA、工作区状态、分支、worktree 路径和冲突事实，不在同一批次拼接 memory、项目 README、模块文档、历史 spec/计划或能力 reference 的全文：

1. 先检查原工作区状态，已暂存、未暂存或未跟踪的非 ignored 改动任一存在时，披露实际路径并停止初始化；不得创建 feature 分支、worktree 或流程文档，也不提供“确认后继续”的放行选项。禁止自动 stash、提交或丢弃；用户自行处理后重新检查，只有工作区干净才允许创建新流程。预检通过后保存原始仓库根、base 分支、不可变 `initial-base-sha` 和原工作区状态，并把 `delivery-base-sha` 初始化为同一 SHA。
2. 比较 Git 目录与 common directory，并排除 submodule。当前工作区是 linked worktree 时暂停，要求从预期的 base worktree 重新显式调用本 skill；不得把当前 linked worktree 作为新流程的工作区。
3. 路径优先级：用户/项目指令指定位置 → 已有 `.worktrees/` → 已有 `worktrees/` → `<repo-root>/.worktrees/<feature-slug>`。仓库内目录必须已被 Git ignore；否则让用户选择添加规则或改用仓库外目录。
4. 检查目标 feature 分支与 worktree 路径；任一已存在即披露实际冲突并暂停，不复用、不挂载现有资产。
5. 创建 feature worktree 和分支，验证实际路径、分支及干净状态。权限、沙箱或路径失败时报告并暂停，禁止回原工作区实施。

初始化不安装依赖、不构建或测试。用户或项目要求的基线检查作为约束传给承担验证的能力；实际失败需要基线区分时由该能力确定范围和命令，不能变成每次初始化的默认门禁。自有只读机械工作按共享协议处理，所依赖结果必须到终态后再消费。

## 生命周期文档

worktree 就绪后立即从下列规范骨架创建 `docs/feature/YYYY-MM-DD-<feature-slug>.md`。初始内容只要求身份和清理所需字段完整；Stage 1 退出前补齐 spec、授权和未验证项，不在设计开始前推演尚不存在的内容。

```markdown
# [功能名称] — 生命周期记录

**创建日期**: YYYY-MM-DD
**Worktree**: <worktree-path>
**分支**: feat/YYYY-MM-DD-<feature-slug>
**Base 分支**: <base-branch>
**Initial Base SHA**: <initial-base-sha>
**Delivery Base SHA**: <delivery-base-sha>
**需求文档**: <现有路径 | 由 Stage 1 spec 生成>
**Spec 文档路径与内容身份**: 暂无
**当前阶段与状态**: Stage 1
**变更面授权**: <当前授权责任与真实缺口>

## 过程文件清单

- `docs/feature/YYYY-MM-DD-<feature-slug>.md` — 生命周期文档

## 能力结果与交付证据

随实际结果记录能力状态、产物及内容身份、验证依据、限制与阻塞。已有报告可引用，不复制专业判断或重建能力内部过程。

## 临时目标观测（稳定后删除）

仅用于评估项目目标，按编排契约复用实际事件；无事件不填占位表。缺项不阻塞执行，全部目标稳定后删除本区及专用统计。

## 进度

- [ ] 1. 最终 Spec
- [ ] 2. 开发与受影响范围验证
- [ ] 3. 评审与授权修复
- [ ] 整合准备
- [ ] 4. 固化、整合与清理
```

文档落盘后产生 `lifecycle_initialized` 外层观察点；未启用外层集成或动作失败时继续。后续按编排契约保存能力返回的状态、产物身份和交付依据；临时观测不参与完成判断。
