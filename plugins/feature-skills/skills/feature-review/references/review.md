# 功能评审

## 评审基线与快照

评审基线是当前用户需求、已固化的 implementation-ready spec（若有）、适用项目和领域规范、完整实际 diff 及现实调用链。旧计划、废弃方案、讨论顺序和历史报告不是当前需求来源，也不得产生“与计划不一致”的 finding。输入存在会改变结论的冲突时报告冲突证据，不自行选择新的业务语义。

首次评审前建立内容快照，目标内容变化后更新快照；每个快照至少记录当前基线身份、目标 HEAD（若适用）和覆盖全部评审路径实际内容的哈希。内容清单按仓库相对路径记录 `added | modified | deleted`；现存路径记录原始字节 SHA-256，删除路径记录固定标记，rename 表示为旧路径删除加新路径新增；使用 Git 枚举时关闭 rename detection（`--no-renames`），避免漏掉旧路径删除。tracked、staged 和 untracked 的目标内容都纳入；可重建构建产物和明确不属于评审目标的过程产物排除。

从建立快照到主代理自审、独立 reviewer 返回和候选裁决结束，目标内容保持只读。消费 reviewer 结果前重新核对身份；内容变化时旧结果只能作为线索，重新建立当前快照。

已有差异检查与评审快照使用相同的完整比较范围；例如执行 `git diff --check` 时指定本次评审基线，不能用默认仅检查未暂存差异的成功结果代表整个交付。未跟踪目标按快照范围另行检查，不为运行检查而暂存或改变内容。

## 双轴评审与事实归属

对同一快照执行两个互不替代的轴：

- **Spec correctness：** 核对当前需求与已固化 spec（若有）中的业务结果、规则、状态转换、外部契约、授权和责任范围：是否遗漏或仅部分实现，已实现行为是否错误，以及 diff 是否引入未经授权的业务变化。
- **Implementation correctness：** 核对现实调用链、项目与领域规范、数据和状态流、事务及集成失败路径；沿业务路径阅读代码时，关键状态、判断和失败处理是否容易追踪，业务事实与跨层处理是否由正确的所有者负责。规范类 finding 指明适用规范的文件与具体规则；代码味道只是调查线索，结构性候选按下述概念净变化条件判断。

两个轴都核对业务事实的归属：需求和已固化最终 spec 只能有一个当前业务定义；代码中的业务事实、状态、配置、派生值和领域判断只能有一个真实所有者。缓存布尔值、平行状态或调用方局部规则只有在能证明不会形成第二事实源时才成立。finding 必须给出当前契约证据或现实可达的错误结果；“可能不同步”本身只是线索。

Implementation correctness 同时核对概念净变化：完成业务结果需要理解的状态、模式、标志、包装层和责任交接是减少、增加还是搬移。只有具体 diff 能证明存在严格更简单、仍承担全部必要责任且处于授权范围内的替代实现时，才形成结构性候选。文件长度、抽象偏好、未来扩展或通过测试不能单独证明问题成立或不存在。

## 独立 Reviewer

首轮完整评审建立快照后，主代理开始双轴自审，同时只派生一次隔离、只读 reviewer。主代理读取 reviewer 结果前完成同一快照的自审。reviewer 不修改代码或报告、不裁决缺陷、不执行修复，也不得派生代理。

reviewer 状态只允许 `unused → running → consumed`。收到最终结果、失败或超时即为 `consumed`；内容变化、修复或重新评审不恢复机会。第二个 reviewer 只有用户明确改变一次上限时允许。

独立 reviewer 是评审角色，不是低成本代理，也不得派生低成本代理。主代理可以把已经确定的机械快照或验证批次另行交给低成本代理，但不能让它替代 reviewer 的判断。

reviewer 能力不得低于主代理：主代理型号可派生时使用同一型号，否则只选择可证明更高档的型号；无法证明时记录 reviewer 不可用并继续主审，不以低档替代。使用隔离上下文与 `reasoning_effort: low`。主代理先完成尚可独立进行的自审，再通过原生事件等待；宿主允许时建议 `300000`–`600000` ms，受沟通频率或接口上限约束时使用允许的较长等待。超时无新事件则继续事件等待，不用重复短等、状态查询或无诊断目的的日志读取代替等待。

派生消息要求 reviewer 先完整读取 [独立 reviewer 契约](independent-reviewer.md)，再读取与快照对应的当前需求、spec、规范、完整 diff 和现实调用链。主代理不注入预期结论、怀疑点或修复方向。

仅在当前显式调用要求文件报告并提供路径时写入；否则在当前回复中汇合自审与 reviewer 候选。主审或 reviewer 任一提出候选时，完整读取 [候选裁决](review-adjudication.md)；没有候选则跳过该文件。reviewer 未完成或不可用时按实际状态披露，不能当作已取得独立 No findings。

## 候选与执行分支

存在候选时，无论是否授权修复，都先按候选裁决契约逐项验证，不直接转发 reviewer 的判断。只把 `confirmed` 作为修复范围；区分恢复已固化契约、改变契约本身与缺少执行权限，只有改变契约才返回需求变化。理论边界、证据不足、仅基于架构偏好和未来扩展的候选拒绝。

- 当前无 finding 且没有未解决阻塞：跳过修复说明，完成验证判断与完成输出。
- 只读评审存在确认 finding：不修改文件、不加载修复说明；完成适用的验证判断，返回证据、影响、建议修复和所需验证，明确哪些问题未修复。
- 存在 `confirmed`、修复已获授权且没有阻止修复的契约或事实缺口：完整读取并执行 [授权修复与复审](review-repair.md)，不逐项重新请求已取得的授权。
- 必须改变契约、缺少执行权限或仍有影响正确性的未决事实：按完成输出的结果分类返回具体缺口，不进入修复。

## 评审覆盖与结束

首次双轴完整主审覆盖高风险路径和现实调用链，并汇合一次独立 reviewer 的结果；不可用或失败时按既有降级规则披露。候选均已裁决、没有确认问题或未解决阻塞且必要验证证据充分时结束，不在同一快照上强制追加第二次主审或定向复核。

目标内容或影响结论的事实变化时，确认哪些既有评审结论仍然有效，只补充受影响范围；无法界定影响范围或变化使原有整体判断失效时，重新完整评审。结论必须覆盖最终快照，披露复用与补充的范围及依据；授权修复后的复核遵循修复流程及其轮次上限，不重新派生独立 reviewer。理论疑虑不能延长循环。

## 非重复验证

验证只取得当前结论需要的机械证据。先检查已有证据是否同时满足：目标内容身份相同；命令依赖的配置和环境没有实质变化；原命令范围覆盖当前结论。三项都满足时直接复用，不因进入评审、负责人要求“更有信心”或时间充足而重复执行。

验证范围和命令由主代理确定。命令完全确定后，按入口资格判断下放；执行身份属于本次 feature-review，不续用 feature-dev 的代理，即使工作目录和命令相同。低成本代理只返回机械证据，不判断 finding、不选择修复或验证范围。

项目明确质量门禁、用户明确要求新的运行结果、已有证据范围不足或授权修复改变了相关内容时，才补充必要验证。所有确认修复稳定后再统一执行受影响检查；不默认每修一个 finding 就运行完整构建。识别命令包含关系，较宽门禁已覆盖编译和目标测试时不重复执行被包含的命令。

需要最终工程验证时，只在最终稳定快照上执行一次。按工程、工作目录、构建产物、端口、数据库、运行时和前后依赖分组；共享 Maven reactor、输出目录、数据库或运行时的命令在同组串行，不共享可变资源的组才并行。失败命令只有代码、配置、命令或环境事实变化后才重跑。

用户明确要求跳过编译或测试时不运行对应命令，并把结论标记为静态验证。没有适用能力或无法执行时记录未验证风险，不用重复评审替代。

对范围外既有检查失败，独立核对其是否由本次改动引入或影响、是否妨碍当前业务结果，以及项目是否明确要求全绿交付。确认无关且无此硬约束时，只保留失败证据和限制，不主动提案或申请扩大修复范围，不把它自动升级为 finding 或交付阻塞；有实际影响或硬约束时保留具体阻塞，不改检查规则掩盖失败。

## 完成输出

本 skill 独立判定评审与授权工作的完成状态：完成当前请求返回 `completed`；必须改变契约返回 `requirements-change-needed`；契约明确但缺少执行权限返回 `requires-user-authorization`；执行失败、影响正确性的未决事实或预算耗尽返回 `blocked`。只读评审完成可仍有 confirmed finding，必须明确列为未修复项；完成评审不等于可以交付。

返回评审快照身份，分别呈现 Spec correctness 与 Implementation correctness 的结论：各轴列出已确认 finding，或说明无 finding、证据限制及其影响。同根因候选按裁决结果合并，但保留涉及的轴及各自证据，不用单一总评掩盖任一轴的未解决问题。同时返回候选处置、实际修复和未解决阻塞、是否修改文件，以及 reviewer 的实际参与状态（完成、失败、超时或不可用）。独立 reviewer 不可用时按既有降级规则完成主审并披露，不能声称已取得独立评审。

同时返回完整评审范围的实际修改路径及既有生产文件影响说明：按实际变更说明控制流、状态、事务、异常、补偿、协议、权限及共享资源或容量的变化，只列相关影响和仍未知的事实。已有说明可以引用，修复改变影响时更新；结论绑定最终评审内容，供调用者直接披露，不让调用者重新分析业务影响。

验证逐项保留内容身份、完整命令、工作目录、影响结果的配置与环境、覆盖范围、退出码、结论及报告引用（若有）；说明哪些证据复用、失效或由新执行补充及原因，不改写旧运行事实。必要元数据未知时不能据此认定可复用，按现实缺口补充必要验证或披露未验证限制。分别报告通过、失败、用户要求跳过、无法执行或未执行；No findings 不代表验证通过。返回后停止，调用者无需补做评审算法或证据裁决。
