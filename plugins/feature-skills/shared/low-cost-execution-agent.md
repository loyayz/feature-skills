# 低成本代理协议

协议标识：`low-cost-execution/v3`

本协议供所有 `feature-*` Skill 在使用低成本代理时共同遵守。它的核心目的，是把已经确定的机械执行及其大段原始输出隔离在主代理上下文之外；它不转移需求、方案、实现策略、finding 裁决、验证范围或流程控制责任。

低成本代理、独立 reviewer 和并行开发代理是不同角色。只有主代理创建、续用和等待低成本代理；低成本代理不得派生代理，独立 reviewer 和并行开发代理也不得建立二级低成本调度。

## 按需加载

每个 `feature-*` Skill 的入口只保留资格初筛规则。当前 Skill 首次确认准备下放一个机械批次时，主代理才完整读取本协议；没有实际下放就不读取。

同一主任务已经完整读取相同协议标识时，后续 Skill 不重复读取。新任务、协议标识变化，或主代理无法确认关键约束仍在当前有效上下文中时重新读取。协议是否已加载不是流程状态，不建立通用台账。

## 模型路由

低成本是运行时能力，不以 Codex 为前提。每次新建低成本代理时，以当前运行时实际公开的代理创建接口、model allowlist 和覆盖能力为准：

1. 在 Codex 中，优先建议显式使用 `gpt-5.6-luna`、`reasoning_effort: low`、`fork_turns: none`；这是一组默认偏好，不是所有运行时必须支持的固定参数。
2. 运行时允许模型覆盖但不提供该组合时，选择能够可靠执行确定性命令并形成简洁证据的最低成本配置，同时使用隔离上下文。
3. 运行时不支持模型覆盖时，使用其原生低成本或隔离代理能力；没有可用代理时，由主代理按当前 Skill 的直接执行规则处理，不阻塞能力本身。
4. 参数被拒绝时保留错误，不重复提交相同参数；只按实际 allowlist 或运行时能力降级一次。
5. 代理发现任务要求选择方案、解释需求、诊断根因、修改受保护文件或申请新授权时，立即返回主代理，不自行提高模型、推理强度或扩大任务。

## 下放资格

满足以下全部条件且不存在下述直接执行情形时，将机械批次交给低成本代理：

- 目的、精确工作目录、完整命令、执行顺序、允许路径、退出码语义和所需返回值已经确定。
- 中途不需要根据结果发明下一条命令，也不需要判断需求、业务语义、授权、实现策略、finding 真伪、验证范围或最终结论。
- 命令非交互且不需要新的用户确认。
- 失败可以原样返回主代理，不要求代理修正代码、环境、依赖或命令。
- 副作用只限只读访问，或主代理预先声明的可重建派生产物。

以下情况可以由主代理直接执行，不为追求形式而派生代理：结果会立即决定下一条尚未确定的命令；所有代理槽都被实际工作占用；运行时无法可靠下放；必须操作主代理持有的交互进程、活动会话、TTY 或不可共享资源；或者只有一条立即完成、无需汇总的微小只读检查且派生成本明显更高。当前 Skill 另有记录要求时，按其本地规则记录；本协议不创建通用例外台账。

## 副作用边界

允许的机械工作包括：

- 精确的只读搜索、状态、路径、哈希、集合和计数查询；
- 主代理已经选定范围和命令的 typecheck、lint、build、test 或其他验证；
- 上述命令按既有工具语义生成的 build、test、cache、coverage、report、log 和临时派生产物；
- 等待并读取本批次启动的同一进程或会话直到终态。

不得下放：

- 修改需求、方案、spec、源码、测试、流程文档或用户资料；
- 选择实现策略、验证范围、finding 裁决、修复方案或生命周期路由；
- commit、merge、rebase、reset、stash 等 Git 写操作；
- 安装、升级或移除依赖；
- 数据库、外部服务或其他持久化系统写入；
- 删除、移动或覆盖用户数据；
- 失败后的自主诊断、命令改写、替代命令或重试。

## 身份、批次与复用

每个低成本代理在首次派生时固定身份：`所属执行范围 + 工作目录 + 单一任务域`。执行范围由当前 Skill 定义。任一身份字段变化都新建代理，不跨执行范围、工作目录或任务域复用句柄。

只有身份完全不变、上下文仍适用、后续批次存在真实顺序依赖，而且运行时支持可靠 continuation 时才续用，包括预先规划的后续工作。相互独立且可以并行的批次使用不同代理。既有上下文已经接收无法在源头压缩的大段输出，或运行时无法可靠续用时，也新建代理。

首次派发前，主代理把当前决策点下、同一身份中所有已经知道且中途无需重新选择策略的机械动作收敛成一个完整批次。不能把单条命令、单个文件或刚发现的字段机械拆成多次唤醒。

后续 continuation 说明本批目的、顺序依赖和完整命令即可，不要求任务此前不可知。已知且无需中间决策的命令仍应一次派发；遗漏命令或无必要拆批计为机械浪费，不以强制更换代理掩盖。失败后的续用仍须主代理取得支持代码、配置、命令或环境修正的事实并重新准备批次，禁止不变重试和代理自主诊断。

同一决策点存在多个相互独立的机械批次时，先启动完整波次，再继续主代理本地工作。真正空闲且结论依赖未完成结果时才使用事件等待；唤醒后统一消费当时已经返回的结果，不逐个短轮询。

## 执行信封

每次首次派发前，主代理形成以下输入；任一必需项缺少时不得下放：

- **执行身份：** 所属执行范围、单一任务域和精确工作目录。
- **宿主契约：** 实际 shell；必要时包含版本；把会影响本批命令的项目指令写成实际约束，不能只给指令文件路径或一句“遵守项目规范”。
- **批次命令：** 完整命令和顺序、允许读取的路径、允许生成的派生产物，以及每条命令的成功、预期否定和失败退出语义。
- **返回契约：** 成功只需 `Passed.`，或逐项列出的必要值；失败只需失败命令、退出码和最小错误片段。

每次唤醒只执行一个预先收敛的根批次，至多发起一次新的执行调用。根执行非零退出时不启动第二次执行、诊断或替代命令，立即按返回契约结束。

如果根执行返回活动进程或会话，继续等待和读取同一进程直到终态仍属于当前批次；不得另起进程诊断，也不得提前返回成功或失败。达到明确超时仍未终止时，只返回 `Incomplete`、原命令、活动会话标识和最小末尾输出。

## 输出隔离与等待

预期产生大量成功日志的命令，在派发前使用工具原生 quiet/reporter 选项，或把完整输出保存为已声明的派生产物。成功只让状态或明确要求的值进入主代理上下文；失败只返回定位所需的最小片段。不得先把完整日志送入代理上下文，再依赖最终回复压缩。

主代理还有可并行工作时不等待。真正空闲时使用运行时原生事件机制；宿主允许时单次等待建议约 `300000`–`600000` ms，受沟通频率或接口上限约束时使用该约束允许的较长等待，由完成、失败或需关注事件提前唤醒。超时后仍无新事件时继续事件等待，不改为反复短等、查状态或读取运行日志。日志只在失败、明确超时或新诊断需要时读取；同一活动进程必须通过读取接口等待时，也使用接口与沟通约束允许的较长等待，直至终态。

## Windows PowerShell 命令契约

主代理负责在派生前把命令准备到可独立执行：

- Windows 宿主使用项目要求的实际 shell；要求 PowerShell 时使用 PowerShell 7。已经位于 PowerShell 中时不再嵌套 `pwsh -Command`，也不混用 Bash、`cmd.exe`、Git Bash 或 WSL 的语法和转义。
- 用 `Test-Path -LiteralPath` 验证关键路径，用 `Get-Command` 验证外部程序。路径使用绝对值或已验证的明确相对值。
- 外部命令和 `$LASTEXITCODE` 判断写成独立语句。复杂参数使用 `[string[]]` 数组并 splat；每个 Maven `-Dname=value` 和测试选择器作为一个完整参数。
- 为 `rg` 无匹配、Git 无 upstream 等预期否定预先声明允许的退出语义。
- 含脚本块或嵌套引号的 PowerShell 在真实执行前用当前解析器检查；解析通过不替代路径、可执行文件和参数语义检查。
- 不拼接可执行命令字符串，不使用 `Invoke-Expression`，不把一个 shell 枚举的路径交给另一个 shell 做破坏性文件操作。
- 从项目指令、CI、README、wrapper 或构建文件取得真实构建入口、运行时和选择器，不从目录名猜测；Windows 中 `npm`/`npx` 缺失时先检查对应 `.cmd`。
- Python 读取 UTF-8 Skill、Markdown 或配置时优先使用 `python -X utf8` 或显式 UTF-8 参数。
- shell、引号、路径、选择器或可执行文件解析失败时原样返回；主代理取得证明新命令正确的证据后，才能形成新的批次。
