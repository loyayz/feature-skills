# 授权修复与复审

仅在候选已裁决为 `confirmed` 且修复已获授权时读取。没有确认 finding 或仅获只读评审授权时不加载。本文件承接[共同评审流程](review.md)的修复分支，不重新启动 Skill、创建独立 reviewer 或重置已有预算。

## 修复与验证

按严重程度处理确认问题，尽量在同一稳定修改点集中相关修复，再按共同流程的非重复验证规则执行一次直接受影响验证。只有修复改变业务语义或产生不同业务可观察选择时，才更新既有标准测试中的直接相关普通用例。禁止越过当前需求和授权面；新事实要求改变契约或缺少执行权限时，返回对应缺口，不自行扩大修复。

同一确认缺陷连续两次实质修复仍未通过直接相关验证时，才完整读取并执行[重复修复失败升级](failure-escalation.md)。未触发时不预读；分析、读文件或重复运行未变化命令不算实质修复。

## 新快照复审与退出

修复后更新内容快照，按需求正确性与实现正确性复核修复内容、受影响调用链及同根因路径，确认原问题已关闭且没有引入新问题。未受影响且依据仍有效的评审结论直接复用；无法界定影响范围或修复使原有整体判断失效时，才重新完整主审。

修复与复核循环最多五轮；局部复核、完整复审和失败升级均不重置该预算。新候选仍按共同流程裁决，不把修复结果当作评审结论，也不为取得第二次 `No findings.` 而重复检查。

确认问题已关闭、最终快照的评审覆盖充分且没有阻塞时，返回共同流程完成验证判断与完成输出。验证复用、最终工程验证及失败分类继续使用共同流程规则，不另设验证门禁；理论疑虑不能延长循环。

达到轮次上限或升级修复仍失败时，保留已完成工作、未解决问题和验证证据，按共同流程返回实际未完成状态，不宣称评审通过。
