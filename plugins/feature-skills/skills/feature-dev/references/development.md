# 功能开发

## 实施就绪

确认当前已固化的 implementation-ready spec 或需求契约没有未解决的业务歧义、授权缺口或查明后会改变生产方案的事实。编码前沿现实调用链形成只存在于当前任务状态中的即时技术映射：把业务结果和受保护行为对应到真实代码责任、调用方、被调用方及技术依赖，不创建正式实施计划或逐任务过程文档。

新的文件、类型、调用方或技术依赖只要服务已固化结果，且不改变业务语义、可观察契约、授权边界或重要运行影响，就更新即时映射并继续。新证据会改变业务规则、权限、安全、事务、一致性、异常结果、补偿、外部契约或重要运行影响时停止修改，返回需要重新收敛或授权的具体需求变化。理论边界或与当前结果没有因果关系的发现直接丢弃。

## 批次与结果汇总

实现方式遵守[入口约定](../SKILL.md#实现方式)。主代理按真实依赖组织尽可能少的内部批次，并负责任务边界、代理数量与预算、修改冲突处理、结果解释和汇总；不为执行方式增加确认点。批次用于控制变更和核对范围，不是独立评审或验证门禁。

不为普通实现创建任务说明、报告、差异包、评审包或额外计划。只有用户明确要求独立实施计划或跨任务交接时才创建相应产物；它不能成为第二份业务语义来源。

## SSOT 与最小实现

已固化的 implementation-ready spec 是业务语义的唯一权威；当前代码中的真实所有者是技术事实的权威。同一业务事实只保留一个来源，不复制状态、真假标记、配置、派生数据或近似规则。调用方需要不同表示时从权威事实派生，不在各调用方保存平行含义。

确需修改时先复用现有事实所有者和项目权威机制，再考虑语言或平台原生能力、项目已有依赖，最后才采用最小新增代码。生产实现遵循 KISS、SSOT、信任层间契约、理论边界快速失败和分层防御责任：

- 入口层承担外部输入、身份、权限和协议边界。
- Domain 只维护业务不变量与状态转换。
- Infra 只承担自身资源、协议和外部系统边界。
- 只有当前层拥有、且由明确需求、接口契约或现实证据证明必要的防御才保留。
- 没有明确异常转换、补偿、资源释放或恢复结果时不新增 `try/catch`。
- 不为人工改库、数据库人为污染、契约外返回或正常链路不可达状态增加清洗、默认值、恢复分支或重复校验。

实现前在当前任务状态明确业务目的、预计影响责任和受保护行为，不预登记逐批精确路径或创建第二份实施计划。稳定修改点使用 Git 状态、相对本次固定比较基线的路径差异和实际 diff 核对范围。服务已固化责任的合理新增路径继续实现；发现未授权删除、越过受保护行为或超出业务责任时，停止并报告具体契约缺口。

## 普通测试

生产设计不为测试便利增加 hook、setter、公开入口、配置开关、依赖抽象或内部状态暴露。只有业务语义变化，或者行为选择变化且产生不同业务可观察结果时，才在职责最接近的既有标准测试层新增或更新直接相关普通用例。

普通参数转发、框架装配、技术性防御、样式、布局、文案、类型声明、配置整理和行为保持型重构不因覆盖率、风险感受或新增文件而自动增加测试。没有适用的既有测试体系时不创建新测试类别或临时测试资产，只如实记录未验证风险。

## 非重复验证

实现期间以静态范围核对为主，不把每个内部批次变成编译或测试门禁。所有相关修改稳定后，收敛一次受影响范围验证批次；只有高风险接口需要提前反馈，或者真实失败需要诊断时，才在稳定点执行更窄的检查。

验证范围和命令由主代理确定。命令完全确定后，按入口资格判断下放；低成本代理只返回机械证据，不选择验证策略、不解释失败，也不修改实现或测试。

选择验证命令时先读取适用项目指令，再按项目脚本、CI、wrapper 和已安装工具确定真实门禁。项目明确要求的验证序列照常执行；在项目未要求分开执行的范围，较宽命令已可靠覆盖的编译或目标测试不再重复。不得为了“最大信心”叠加同类门禁。

验证证据至少关联当前内容身份、完整命令、工作目录、影响结果的配置与环境身份、覆盖范围、退出码与结论，以及已登记的日志或报告路径（若有）。相同内容、相同命令和没有实质环境变化时复用已有成功证据；失败命令只有代码、配置、命令或环境事实发生变化后才重跑，禁止不变重试。修补前定位实际路径，复杂 shell 先解析，修补后核对真实 diff，不能把补丁尝试当作有效变化。多个修改或确认修复尽量集中到稳定点后一次验证，不默认逐项运行完整构建。

用户明确要求跳过编译或测试时不运行对应命令，并把结果明确报告为静态验证。无法执行的适用验证记录为未验证风险，不以重复静态检查伪装成通过。

检查失败先判断与本次交付的因果关系。证据确认未由本次改动引入或影响、且不妨碍当前业务结果的范围外既有失败，只报告失败证据和影响，不主动提案或请求扩大范围修复，也不自动作为交付阻塞；不得修改检查规则掩盖失败。项目明确要求全绿才可交付，或失败确实妨碍当前结果时，保留阻塞并说明具体依据，不自行豁免。

## 完成

只有以下条件全部满足才结束：

- 已固化业务结果已实现，实际 diff 没有越过变更面或受保护行为；
- SSOT、KISS、快速失败和分层责任在最终实现中成立；
- 命中测试价值条件的普通用例已更新，未命中时没有为流程形式新增测试；
- 一次收敛后的受影响范围验证已通过，或者用户要求跳过的范围及无法验证风险已如实记录；范围外既有失败已按上述因果关系与项目约束独立报告；
- 没有尚未处理且会改变业务方案、授权或交付正确性的事实。

满足上述条件返回 `completed`，附实际修改路径、业务结果、执行方式、当前内容身份、受影响验证证据和限制。验证分别标明通过、失败、用户要求跳过、无法执行或未执行；没有新运行时不得声称取得新结果，未知元数据不能证明可复用。

需要改变已固化需求时返回 `requirements-change-needed`；契约明确但缺少执行权限时返回 `requires-user-authorization`；工具、环境、依赖或证据阻塞时返回 `blocked`。每种未完成结果给出已完成范围、具体缺口和继续所需条件，不让调用者从叙述推测状态，然后停止。
