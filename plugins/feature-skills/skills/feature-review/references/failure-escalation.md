# 重复修复失败升级

同一确认缺陷连续两次实质修复仍未通过直接相关验证时，停止第三次盲改。仅分析、读文件或重复运行未变化命令不算修复尝试。

1. 固化预期行为、当前行为、两次实际差异、验证命令、退出码和稳定错误特征。
2. 逐字读取失败输出，沿调用方、依赖、状态变化和错误处理重查现实路径；验证版本、路径、权限、配置、数据和环境假设。
3. 根据证据形成可证伪根因假设，记录支持证据、反证和最小区分检查；数量由尚未排除的现实原因决定，不为固定数量凑假设。
4. 优先执行信息增益最高的非破坏检查，根据证据选择与前两次本质不同的方案。
5. 最多执行两次升级修复，一次只实施一个方案；稳定后运行一次直接相关验证。

验证通过后重新检查同根因现实链路，再返回完整评审。两次升级修复仍失败时，记录已验证事实、已排除假设、最后失败证据、剩余风险和建议下一步，然后停止。禁止继续盲改、降低门禁或把范围外修改包装成修复。
